# Start a new collaboration epoch when restoring a revision

A Markdown revision restore commits a new body version and starts a new BodyEpoch for the same document ID. The writer rebuilds collaborative state from the selected AST snapshot and publishes the new epoch after the PostgreSQL commit. Updates and MoveNode/DeleteNode commands created in an earlier epoch are held locally for user review and are never merged automatically into the restored body. A user may deliberately reapply selected changes against the current body, producing new operations in the new epoch. This prevents an offline client from silently restoring content that the revision restore removed, while preserving its unsynced work for review. BodyEpoch is an application protocol boundary, not a Yjs state vector or a second document identity.

The first recovery UI shows the restored body beside the locally edited body and lets the user copy chosen text or blocks into the current editor. Copying creates normal edits in the new epoch; the application does not automatically map old node IDs, anchors, or binary updates into it. Pending work remains available until the user resolves or discards it, subject to current read access and the device cleanup policy.
