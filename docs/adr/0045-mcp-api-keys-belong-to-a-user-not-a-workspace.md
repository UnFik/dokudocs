# MCP API keys belong to a User, not a workspace

An outside AI client connects to Dokudocs (`/mcp`, Streamable HTTP in the Go API) with an MCP API key the User created. The key is shown once, stored as a hash, and reaches every workspace the User belongs to with that User's rights; leaving a workspace ends its reach there on the next call. It may expire after 7, 30 or 90 days or never, and its owner can revoke it at any time. There is no per-workspace switch: a Superadmin holds the brake instead, with a platform switch that stops every key, rate limits per key for reads and writes, a result size cap and the audit retention, all kept in the database. Every call is audited (key, tool, resource, outcome, time, never content) for the key's owner and Superadmins.

Rejected: OAuth with dynamic client registration (heavier, and the clients in use accept a static key), reusing the session JWT (cannot be revoked, ADR-0035), and binding a key to one workspace (the owner wants one key for all their work). The cost is a larger blast radius for a leaked key, which the no-public-link rule in ADR-0044, revocation, the audit trail and the platform switch are there to contain.
