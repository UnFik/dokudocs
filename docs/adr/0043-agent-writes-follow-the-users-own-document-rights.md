# Agent writes follow the User's own document rights, as suggestions from chat and as edits through MCP

The Agent writes content through the collaboration service, under the same rule that applies to the User typing: edit rights write to the body, suggest rights write Suggestions, view rights write nothing. From a Conversation inside Dokudocs every content change is a Suggestion labelled AI assisted, whatever the User's rights, and every other action (create, move to trash, rename, project members) waits for the User to approve it in the chat. Through MCP an outside client with edit rights writes to the body directly; a named revision is made first and the history records the User and the MCP API key, so one restore undoes it. Writes are targeted operations (replace text, insert after a heading, append a section) carrying the version the Agent read, and are refused when the document has changed since; whole-document replacement is not offered because it would overwrite people editing at the same time.

Rejected: letting the Agent write straight from chat (no human sees instructions hidden in a document before they take effect), a separate Go writer for Yjs state (ADR-0029 keeps the collaboration service as the only writer), and inline AI marks on direct MCP edits (they become marks someone has to clean up, which is what Suggestions are for). Architecture documents were read-only to the Agent at first: one wrong operation on the canvas graph can break a diagram. [ADR 0049](0049-the-agent-edits-architecture-documents-with-approved-operations.md) lets the Agent edit them.
