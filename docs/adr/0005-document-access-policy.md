# Use one effective document access policy

Dokudocs resolves document access from current workspace membership, project membership/visibility, explicit document visibility, direct grants, draft status, and lifecycle before any read or write. Explicit `workspace`/`private` visibility overrides project inheritance; a direct document grant bypasses a private project's membership requirement but still requires workspace membership. A document grant does not expose private-project metadata or its member list. Project `workspace` metadata is visible to workspace members; a private project's metadata is visible to its project members and workspace owner/admin. Workspace owner/admin may read private content, while drafts remain readable only to the author or effective edit/owner users. A public link requires a valid token, including when its document is considered by the workspace chatbot. Only the current document owner grant or workspace owner/admin may assign, demote, or remove an `owner` grant; effective edit access alone cannot transfer ownership. This shared policy costs a coordinated change across list/detail/editor/retrieval, but prevents the existing mismatch in which stored visibility and grants do not constrain every read path.
