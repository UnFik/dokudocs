# Link sign-in identities by provider subject, never by email alone

A sign-in identity (Google now, GitHub later) is matched to a User by `(provider, provider_user_id)` first; the email a provider reports is only a hint. When an unlinked identity arrives with an email that already belongs to a local account, the identity links automatically only if that account's email is verified and the provider reports the email as verified, and the password stays. If the local account's email is not verified, the Google login takes the account over: its `password_hash` is cleared, `email_verified_at` is set, and the identity is linked, because an unverified password may have been set by someone who does not own the address (pre-hijacking). A signed-in User can also link an identity from Settings, with a different email, and can unlink one only while another way to sign in remains.

Rejected: auto-linking on email alone (pre-hijack and provider-claim attacks), and refusing every email collision (a person who registered locally could never use Google). Clearing the password costs a never-verified account its password login, and there is no password reset yet, so Settings offers "Set password" to a User who has none. Issued JWTs cannot be revoked, so a pre-hijacker's token stays valid until it expires (24 hours by default).
